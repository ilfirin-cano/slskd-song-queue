# slskd Song Queue

Отдельный HTTP-сервис с веб-интерфейсом: принимает список композиций, ищет совпадения через API уже запущенного контейнера slskd и добавляет выбранные файлы в его очередь загрузок. Сам slskd в этот Docker Compose не входит и не устанавливается повторно.

## Подключение к существующему slskd

1. Убедитесь, что контейнер slskd запущен:

   ~~~bash
   docker ps
   ~~~

2. Узнайте Docker-сеть, к которой подключён контейнер (здесь предполагается, что его имя — slskd):

   ~~~bash
   docker inspect slskd --format '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}'
   ~~~

   Используйте имя одной из этих сетей в переменной SLSKD_NETWORK. Если контейнер называется иначе, укажите его DNS-имя или сетевой alias в SLSKD_URL.

3. Создайте локальный файл настроек:

   ~~~bash
   cp .env.example .env
   ~~~

4. Отредактируйте .env:
   - SLSKD_NETWORK — существующая Docker-сеть slskd, например slskd_default;
   - SLSKD_URL — адрес API slskd внутри этой сети, обычно http://slskd:5030;
   - SLSKD_API_KEY — API key из настроек Web/API slskd.

5. Запустите только приложение:

   ~~~bash
   docker compose up -d --build
   ~~~

6. Откройте веб-интерфейс: http://localhost:8080.

Важно: внешний Docker network должен уже существовать. Compose этого проекта не создаёт, не перезапускает и не изменяет контейнер slskd.

## Поиск и скачивание

- В очередь добавляются только файлы с расширениями .mp3 и .flac. Файлы .lrc и остальные форматы игнорируются.
- MP3 имеет приоритет над FLAC.
- В настройках интерфейса доступны длительность первого и повторного поиска, повторный поиск ненайденных треков и число одновременно активных поисков.
- Параллельность ограничена 2 активными поисками — именно такой предел установлен в slskd начиная с 0.24.0. В интерфейсе нельзя выбрать значение больше 2.
- Старт следующего API-поиска отделён от предыдущего минимум одной секундой. Сами поиски и их опрос результатов могут выполняться параллельно.
- Если параллельный первый проход вернул пустые результаты, приложение автоматически перепроверяет такие же поисковые запросы строго по одному. Это контрольный проход против пустых ответов при конкурентном обновлении состояния поиска в slskd.
- Если после контрольного прохода трек всё ещё не найден и включён повторный поиск, запускается более широкий второй проход.
- Изменяющие API-запросы к slskd (POST и отмена поиска через DELETE) сериализуются и ограничиваются интервалом между стартами; при HTTP 429 сервис повторяет запрос с задержкой.
- Как только для трека найден подходящий файл, приложение добавляет его в очередь slskd. Фактические загрузки идут в slskd параллельно с поисками следующих треков.

### Прерывание batch

Кнопка «Прервать» останавливает активные поиски через DELETE /api/v0/searches/{id}, а новые поиски из текущего списка больше не запускаются. Уже переданные в slskd загрузки не отменяются и продолжаются; это сделано намеренно, чтобы прерывание поиска не отменяло файлы, которые пользователь уже поставил в очередь.

## Рекомендации и чарты Last.fm

Во второй вкладке веб-интерфейса можно указать API key Last.fm и запросить один из поддерживаемых публичных списков:

- похожие треки для одной или нескольких исходных композиций (track.getSimilar);
- популярные треки исполнителя (artist.getTopTracks) или похожих исполнителей (artist.getSimilar);
- популярные треки по музыкальному тегу (tag.getTopTracks);
- топ треков пользователя за выбранный период (user.getTopTracks), любимые треки (user.getLovedTracks) и недельный трековый чарт (user.getWeeklyTrackChart);
- глобальный чарт (chart.getTopTracks) и чарт по стране (geo.getTopTracks).

Это набор методов каталога и чартов Last.fm, а не один универсальный рекомендательный алгоритм. Для запросов используется API key; отдельная авторизация пользователя Last.fm для этих read-only методов не нужна. API key хранится в localStorage браузера и передаётся серверу только вместе с запросом рекомендаций. Вводить его в `.env` не требуется. Используйте интерфейс только в доверенной сети или через HTTPS: при обычном HTTP ключ передаётся без шифрования.

Списки треков можно выборочно перенести в первую вкладку. После переноса проверьте список и нажмите «Найти и скачать», чтобы запустить поиск MP3 / FLAC в slskd. Список похожих исполнителей показывается отдельно и напрямую в очередь треков не переносится.

Новый endpoint приложения: `POST /lastfm/recommendations`. Он принимает `api_key`, `mode` и параметры соответствующего метода Last.fm.

## API

- GET /health — состояние сервиса.
- GET /settings — настройки по умолчанию.
- POST /songs — создать batch поиска.
- GET /batches/{batch_id} — статусы и прогресс.
- POST /batches/{batch_id}/cancel — прервать поисковую часть batch.

Пример отправки списка:

~~~bash
curl -X POST http://localhost:8080/songs \
  -H 'Content-Type: application/json' \
  -d '{"songs":[{"artist":"Daft Punk","title":"Giorgio by Moroder"},{"artist":"Massive Attack","title":"Teardrop"}],"max_parallel_searches":2}'
~~~

## Настройки окружения

| Переменная | Назначение | По умолчанию |
|---|---|---:|
| SEARCH_DURATION_SECONDS | Длительность первичного поиска | 25 |
| DEEP_SEARCH_DURATION_SECONDS | Длительность одного поискового запроса второго прохода | 60 |
| RETRY_NOT_FOUND_BY_DEFAULT | Включать второй проход по умолчанию | true |
| MAX_PARALLEL_SEARCHES | Число одновременно активных поисков (максимум 2) | 2 |
| SEARCH_START_INTERVAL_SECONDS | Минимальный интервал между стартами API POST | 1 секунда |
| SLSKD_429_RETRIES | Число повторов при HTTP 429 | 5 |

В настройках веб-интерфейса можно задать число параллельных поисков для конкретного списка. Интервал старта нельзя уменьшить ниже одной секунды.

## Важные замечания

- Сервис подключается к существующему slskd по внутренней Docker-сети; он не содержит отдельного экземпляра slskd.
- Состояние batch хранится в памяти процесса. После перезапуска song-queue история batch не восстанавливается, но сами трансферы продолжают управляться slskd.
- Совместимость конкретных полей API зависит от версии slskd.
- Не публикуйте порты приложения и slskd в интернет без аутентификации и сетевой защиты. Не добавляйте .env или API key в Git.
- Соблюдайте законодательство об авторском праве и правила Soulseek.
