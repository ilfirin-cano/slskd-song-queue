# slskd Song Queue

Отдельный HTTP-сервис с веб-интерфейсом: принимает список композиций, ищет совпадения через API уже запущенного контейнера slskd и добавляет выбранные файлы в его очередь загрузок. Сам slskd в этот Docker Compose не входит и не устанавливается повторно.

## Сетевая схема: весь трафик через Gluetun

`song-queue` использует `network_mode: "container:${GLUETUN_CONTAINER:-gluetun}"`: его исходящий сетевой трафик идёт через сетевой namespace и VPN/firewall уже запущенного контейнера Gluetun. Сам Gluetun должен быть запущен до запуска этого Compose-проекта. Значение `GLUETUN_CONTAINER` — точное имя контейнера; по умолчанию `gluetun`. Если в `docker ps` он называется `gluetune`, укажи `GLUETUN_CONTAINER=gluetune` в `.env`.

Поскольку `song-queue` разделяет сеть Gluetun, в его Compose-файле больше нет `ports:` и `networks:`. Публикация веб-порта и подключение к Docker-сети slskd настраиваются на сервисе Gluetun.

### 1. Узнать Docker-сеть slskd и её подсеть

Убедитесь, что контейнер slskd запущен, затем выполните:

~~~bash
docker inspect slskd --format '{{range $name, $_ := .NetworkSettings.Networks}}{{println $name}}{{end}}'
~~~

Ниже предполагается имя сети `slskd_default`. Узнайте её подсеть (CIDR):

~~~bash
docker network inspect slskd_default --format '{{range .IPAM.Config}}{{println .Subnet}}{{end}}'
~~~

Подставьте фактическое имя сети и подсеть в следующую конфигурацию Gluetun.

### 2. Изменить Compose-файл Gluetun

В Compose-файле уже существующего Gluetun добавьте в сервис `gluetun` следующие параметры. Не заменяйте ими остальные настройки VPN; объедините `ports`, `environment` и `networks` с уже имеющимися секциями:

~~~yaml
services:
  gluetun:
    ports:
      - "8081:8081/tcp"
    environment:
      # Разрешить входящие подключения к веб-интерфейсу на порту контейнера 8081
      FIREWALL_INPUT_PORTS: "8081"
      # Разрешить локальный доступ к slskd по его Docker-подсети.
      # Замените пример на результат docker network inspect.
      FIREWALL_OUTBOUND_SUBNETS: "172.20.0.0/16"
    networks:
      - default
      - slskd

networks:
  default: {}
  slskd:
    external: true
    name: slskd_default
~~~

Если у Gluetun уже есть собственные сети, сохраните их и добавьте `slskd`; не дублируйте ключи YAML. Если `FIREWALL_INPUT_PORTS` или `FIREWALL_OUTBOUND_SUBNETS` уже заданы, допишите нужный порт/подсеть в существующую строку через запятую, не затирая прежние значения.

`FIREWALL_OUTBOUND_SUBNETS` нужен для локального обращения через Docker-сеть к `slskd`; без этого строгий firewall Gluetun может заблокировать доступ к API slskd. Весь обычный внешний трафик `song-queue`, включая Last.fm, остаётся за VPN kill switch. См. [документацию Gluetun по сетевому namespace](https://github.com/qdm12/gluetun-wiki/blob/main/setup/connect-a-container-to-gluetun.md), [публикации портов](https://github.com/qdm12/gluetun-wiki/blob/main/setup/port-mapping.md) и [firewall](https://github.com/qdm12/gluetun-wiki/blob/main/setup/options/firewall.md).

Пересоздайте/обновите Gluetun через его собственный каталог и Compose-файл. Gluetun должен быть запущен до `song-queue`.

### 3. Настроить Song Queue

Создайте или обновите локальный `.env`:

~~~bash
cp .env.example .env
~~~

Задайте `GLUETUN_CONTAINER` по фактическому имени из `docker ps`, `SLSKD_URL` (обычно `http://slskd:5030`) и `SLSKD_API_KEY`. `slskd` должен быть доступен по DNS-имени из Docker-сети, подключённой к Gluetun.

Обновите и запустите приложение:

~~~bash
git pull
docker compose up -d --build
~~~

Веб-интерфейс теперь доступен на порту **8081**: `http://localhost:8081` или `http://IP_СЕРВЕРА:8081`.

Важно: если Gluetun будет пересоздан (получит новый container ID), пересоздайте и `song-queue`, чтобы он подключился к новому сетевому namespace:

~~~bash
docker compose up -d --build --force-recreate
~~~

## Поиск и скачивание

- В очередь добавляются только файлы с расширениями .mp3 и .flac. Файлы .lrc и остальные форматы игнорируются.
- MP3 имеет приоритет над FLAC.
- В настройках интерфейса доступны длительность первого и повторного поиска, повторный поиск ненайденных треков и число одновременно активных поисков.
- В интерфейсе можно задать от 1 до 20 одновременно активных поисков. Это верхний предел самого приложения; фактически допустимое значение зависит от используемой сборки slskd. Если сервер не поддерживает выбранную параллельность, уменьшите значение.
- Старт следующего API-поиска отделён от предыдущего минимум одной секундой. Сами поиски и их опрос результатов могут выполняться параллельно.
- Если параллельный первый проход вернул пустые результаты, приложение автоматически перепроверяет такие же поисковые запросы строго по одному. Это контрольный проход против пустых ответов при конкурентном обновлении состояния поиска в slskd.
- Если после контрольного прохода трек всё ещё не найден и включён повторный поиск, запускается более широкий второй проход.
- Изменяющие API-запросы к slskd (POST и отмена поиска через DELETE) сериализуются и ограничиваются интервалом между стартами; при HTTP 429 сервис повторяет запрос с задержкой.
- Как только для трека найден подходящий файл, приложение добавляет его в очередь slskd. Фактические загрузки идут в slskd параллельно с поисками следующих треков.
- Повторное нажатие «Найти и скачать» запускает новый список: если предыдущий поисковый проход ещё не завершён, приложение сначала останавливает его и дожидается закрытия активных поисков, затем начинает новую очередь. Уже добавленные в slskd загрузки не отменяются; их мониторинг продолжается в фоне.
- Если slskd не подтверждает остановку предыдущего поиска за 120 секунд, новый список не запускается и интерфейс показывает ошибку вместо того, чтобы допустить нежелательное наложение поисков.

### Прерывание batch

Кнопка «Прервать» останавливает активные поиски через DELETE /api/v0/searches/{id}, а новые поиски из текущего списка больше не запускаются. Уже переданные в slskd загрузки не отменяются и продолжаются; это сделано намеренно, чтобы прерывание поиска не отменяло файлы, которые пользователь уже поставил в очередь.

## Музыкальные рекомендации Last.fm

Вкладка Last.fm предназначена для открытия новой музыки, а не для просмотра статистических чартов. Сначала подключите свой аккаунт через API key и Shared Secret из Last.fm API Account. Приложение использует стандартный desktop-auth flow Last.fm: `auth.getToken` → подтверждение доступа пользователем на Last.fm → `auth.getSession`. Пароль Last.fm не запрашивается.

Поддерживаются четыре сценария:

- **Персональные рекомендации Last.fm.** На основе топа ваших треков за последние 3 месяца приложение ищет похожие композиции через `track.getSimilar`, близких исполнителей через `artist.getSimilar` и добавляет их популярные треки. Уже прослушанные треки исключаются. Используются документированные методы API; отдельный `user.getRecommendedArtists` не вызывается.
- **Похожие на мои прослушивания.** Берутся последние прослушивания либо топ-треки за выбранный период. Для нескольких часто повторяющихся треков запрашиваются похожие композиции, а для характерных исполнителей — похожие артисты и их треки. Уже прослушанные композиции исключаются. Кандидаты объединяются, дубликаты удаляются, а повторы рекомендаций от разных исходных треков повышают позицию.
- **По исполнителю.** Last.fm подбирает похожих исполнителей, затем приложение собирает их популярные треки.
- **По жанру / тегу.** По популярным исполнителям выбранного тега находятся близкие артисты, после чего собираются их треки. Это рекомендация по музыкальному окружению тега, а не просто выдача глобального чарта.

В каждой строке показывается, на основе какого исходного трека, исполнителя или персональной рекомендации появился кандидат. Отмеченные треки можно передать в первую вкладку для поиска MP3 / FLAC через slskd.

### Подключение и хранение ключей

Введите API key и Shared Secret, нажмите «Подключить аккаунт Last.fm», откройте ссылку Last.fm и разрешите доступ. Вернитесь в приложение и нажмите «Я разрешил доступ — завершить подключение».

API key, Shared Secret и session key сохраняются сервером в `./data/lastfm_credentials.json`. Каталог `./data` подключён как `/data` volume и добавлен в `.gitignore`; файл создаётся с правами `0600`. Не публикуйте его и не копируйте в репозиторий. Отключение аккаунта из интерфейса удаляет сохранённые данные.

Session key может быть отозван в настройках Last.fm. Если Last.fm возвращает HTTP-ошибку, приложение показывает часть тела ответа Last.fm (если сервер её передал), чтобы было видно код и причину ошибки. Если запрос персональных рекомендаций вернул ошибку авторизации, отключите и подключите аккаунт заново.

Документация Last.fm: [desktop authentication](https://www.last.fm/api/desktopauth), [track.getSimilar](https://www.last.fm/api/show/track.getSimilar), [artist.getSimilar](https://www.last.fm/api/show/artist.getSimilar), [user.getRecentTracks](https://www.last.fm/api/show/user.getRecentTracks), [user.getTopTracks](https://www.last.fm/api/show/user.getTopTracks).
## API

- GET /health — состояние сервиса.
- GET /settings — настройки по умолчанию.
- POST /songs — создать batch поиска.
- GET /batches/{batch_id} — статусы и прогресс.
- POST /batches/{batch_id}/cancel — прервать поисковую часть batch.

Пример отправки списка:

~~~bash
curl -X POST http://localhost:8081/songs \
  -H 'Content-Type: application/json' \
  -d '{"songs":[{"artist":"Daft Punk","title":"Giorgio by Moroder"},{"artist":"Massive Attack","title":"Teardrop"}],"max_parallel_searches":5}'
~~~

## Настройки окружения

| Переменная | Назначение | По умолчанию |
|---|---|---:|
| SEARCH_DURATION_SECONDS | Длительность первичного поиска | 25 |
| DEEP_SEARCH_DURATION_SECONDS | Длительность одного поискового запроса второго прохода | 60 |
| RETRY_NOT_FOUND_BY_DEFAULT | Включать второй проход по умолчанию | true |
| MAX_PARALLEL_SEARCHES | Число одновременно активных поисков по умолчанию (интерфейс: 1–20) | 5 |
| SEARCH_START_INTERVAL_SECONDS | Минимальный интервал между стартами API POST | 1 секунда |
| SLSKD_429_RETRIES | Число повторов при HTTP 429 | 5 |

В настройках веб-интерфейса можно задать число параллельных поисков для конкретного списка (от 1 до 20). Значение MAX_PARALLEL_SEARCHES задаёт начальное значение поля; его также можно изменить в .env. Интервал старта API-запросов нельзя уменьшить ниже одной секунды.

## Важные замечания

- Сервис подключается к существующему slskd через Docker-сеть, присоединённую к Gluetun; он не содержит отдельного экземпляра slskd.
- Весь исходящий трафик `song-queue` разделяет VPN-маршрут и firewall Gluetun. Доступ к Docker-подсети slskd является отдельным локальным разрешением.
- Состояние batch хранится в памяти процесса. После перезапуска song-queue история batch не восстанавливается, но сами трансферы продолжают управляться slskd.
- Совместимость конкретных полей API зависит от версии slskd.
- Не публикуйте веб-интерфейс в интернет без аутентификации и сетевой защиты. Не добавляйте `.env` или API key в Git.
- Соблюдайте законодательство об авторском праве и правила Soulseek.
